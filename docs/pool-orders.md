# 需求池：超前下单的单子格式

超前下单是指：有空的时候先把选题和写法想好，作为需求放进需求池；之后手头有多少智能体，
就让多少去认领，照单子写。本页规定一张单子写什么、怎么写，2026-11-19 定下。

一张单子就是需求池里的一条写作需求：一个标题、几项属性，加一段简介。下面的格式只用需求已有的
字段，不新增字段；写法相关的内容都写在简介里。各属性在作品上留不留、Obsidian 里看不看得到，
见 [work-properties.md](./work-properties.md)。

## 一、下单入口

两个入口下的是同一种需求，单子格式相同。

| 入口 | 适合 | 草稿 | 能设的属性 |
| --- | --- | --- | --- |
| Obsidian 选题池库（rssd-obsidian 的 README，Topic pool 一节） | 一张一张地想、改 | `Topics/<站点>/<栏目>/` 下还没执行 **Save this topic to the Center** 的笔记 | `title`、`priority`、`type`、`topic-key`、`due`；正文就是简介 |
| `rssd center pool-add`（[HEADLESS.md](../HEADLESS.md) 的 Topic pool 一节） | 一次下一批 | 下单前用 `--dry-run` 检查 | `title`、`brief`、`priority`、`workType`、`topicKey`、`requiredLocales`、`lead`、`adaptedFrom` |

单子在没人认领之前都可以修改、撤回。一经认领，单子和栏目规则一起冻结。

## 二、属性

| Obsidian 属性 | pool-add 字段 | 怎么填 |
| --- | --- | --- |
| `title` | `title` | 一句话：只表达一个意思，用自然的短语或完整问句，保留辨认主题所需的名称。不用两段式，冒号换成逗号或破折号也算（写作协议 `contracts/article-writing-policy.mjs`）。历史单子不在标题里写日期，日期写在记录字段。Center 按标题的主题查重（`contracts/topic-repeat.mjs`），同栏目已有作品或未完成的单子用了同一主题，就会被拒。成文时可以改标题，但首选单子上的标题 |
| `priority` | `priority` | 整数，越大越先被认领；Obsidian 里取 -100 到 100 |
| `type` | `workType` | `article` 或 `note`；留空用栏目默认。只能选栏目接受的类型 |
| `topic-key` | `topicKey` | 可选。换个说法也算同一题时，用同一个键防重 |
| `due` | 无 | 默认不填，单子不限期。只有过了某天再写就没有意义的选题才填；到期的单子不能认领，见第六节 |
| 无 | `requiredLocales` | 超前下的单子默认中文和英文两版，不填就是两版。Obsidian 下的单子不能设，总是两版 |
| 无 | `lead` | 选题由什么启发，例如热榜词。只是线索，不是来源 |

## 三、简介

简介原样交给写作方，排在写作规则之后，作为“本篇要求”。按下面的小标题写，用不到的段落可以省略，
“读者问题”“写法”“必读材料”不能省。

```markdown
## 读者问题
这篇要回答什么，写给谁。

## 写法
角度：……
结构：先……再……最后落到……
篇幅：约 …… 字

## 必读材料
- [题名](链接)：支撑哪一部分
- 补充检索方向：……

## 配图
用原文的哪张图，或者画一张什么图。

## 边界
- 不写……
- 不能写成亲测的：……

## 品牌
挂载：scholay-platform
带法：正文用 Scholay 科研助手实操并配截图，文末带 Scholay 学术一站式平台尾注
```

每张单子都写“品牌”一段：点名要挂的品牌和带法，或者只写一行“不带”。品牌挂载跟着单子走，
不绑定栏目，和人格的挂载是同一种做法：单子上点名一个，或者写明不用（见
[persona-voice.md](./persona-voice.md) 第三节）。将来品牌进入 Center 的挂载库后，这一段换成单子上的
结构化字段，写法照现在的两种情况对应过去。

- 品牌用品牌库里的编号：`scholay-platform`（Scholay 学术一站式平台）、`enterscholar`（恩特学术）、
  `site:<站点>`（各站自己的品牌），定义在 `desktop/scripts/agent/brand-library.mjs`。
- 带法有两种：“正文用 Scholay 科研助手实操并配截图，文末带尾注”，即方法百科的 Scholay 实操系列；
  以及“只带文末尾注”。
- 2026-11-19 起，只有方法百科的 Scholay 科研助手实操系列带 Scholay 品牌，其余单子写“不带”。

现状有一处还没跟上：栏目规则的固定文字仍写着参考文献之后由站点品牌库挂载 Scholay、当前站点和
恩特学术的品牌信息（`contracts/editorial-column-policy.mjs`），桌面端也按站点挂尾注
（`brand-library.mjs` 的 `siteBrandIds`）。规则排在单子之前，所以写了“不带”的单子目前仍会带站点尾注，
要等品牌改成按单子挂载之后，“不带”才真正生效。

“必读材料”列出下单时已经找到的一手来源。认领的一方写作时仍须自己读原文，读不到的不能当来源用。
篇幅在“写法”里写一个大致字数即可，交稿时不检查字数。

## 四、按栏目增加的段落

| 栏目 | 增加什么 |
| --- | --- |
| 今日学术 `academic/calendar` | `## 记录字段`：分类（站点 `yearCategories` 之一）、开始和结束日期（事项实际开放或截止的日期，不是公告日）、日期依据（例如“申请截止：北京时间 16:00”）、发布机构和写明日期的原文链接，以及这项惯例和当年安排的区别 |
| 昔日学术 `academic/history` | `## 记录字段`：年份、月日、学科史领域、事件类型、重要度（S、A、B）、写明这一天的来源。核实不到具体某一天的事件不下单 |
| 学界犀闻 `academic/briefings` | “必读材料”按话题分组，至少两个互相独立的话题；“写法”写明把它们串起来的共同问题 |
| 笔记（任何栏目，`type: note`） | 只写一个看点。图片承担主要信息，“配图”一段要写具体 |

两种记录的字段定义见 `contracts/rssd-record.cjs`，写作要求见 `desktop/scripts/agent/center-record.mjs`。

## 五、单子里不写的

下面这些由栏目决定，认领时 Center 会挂上当时的最新版本。写进单子只会过期，或者和新规则冲突：

- 写作规则、写作协议和它的版本或哈希
- 文体、内容家族、技能、栏目范围和必备要素
- 配图下限、替代文字长度等配图规则
- 署名人格、发布去向
- 批次编号、时区备注、下单流程说明

## 六、已定的规则

2026-11-19 定下：

| 问题 | 规则 | 现状 |
| --- | --- | --- |
| 成文时能否改标题 | 不限制改标题，但首选单子上的标题 | 已是现状：写作方交稿时可以给出自己的标题 |
| 是否要英文版 | 超前下的单子默认中英两版 | 已是现状：不设 `requiredLocales` 时就是两版 |
| 过期的单子 | 基本都下不限期的单子。设了截止时间的，到期后不能认领；要再写，先把截止时间改晚或清空，恢复成可认领 | **还没实现**：Center 认领时只按优先级和入池先后排，不看截止时间（rssd-center `rssd/store.cjs` 的 `claim`）。截止时间的修改和清空已经可以做：Obsidian 改 `due` 后保存，或者用需求的定义修改把 `dueAt` 设为 `null`。pool-add 下单时设不了截止时间 |
| 篇幅 | 在简介的“写法”里简单约束 | 已是现状：只是文字要求，交稿时不检查字数 |
| 标题 | 一句话，不用两段式；历史单子的日期不进标题 | 已是现状：写作协议本来就这样要求；2026-11-19 已把 metho 和学术之门排队单子的标题改成一句话 |
| 品牌 | 跟着单子走，和人格同一种挂载做法：每张单子在“品牌”一段点名品牌和带法，或写“不带”；不绑定栏目 | 只有方法百科的 Scholay 科研助手实操系列带 Scholay（正文实操加文末尾注），其余写“不带”。栏目规则和桌面端仍按站点挂尾注，“不带”要等品牌改成按单子挂载后才生效 |
