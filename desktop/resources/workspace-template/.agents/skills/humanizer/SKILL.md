# 自然表达

只处理实际出现的问题：没有信息的开场与收尾、为强调而写的转折、机械排比、夸大修饰和聊天残留。作者有意的结构、必要限定、引文和专名保持原意；某个词出现本身不是必须改写的理由。

先理解正文与读者，再在授权范围内集中修订一次。与 copy-editing 同用时合并为同一轮修订，避免同一段来回改写。只有识别不清的模式才查 [表达模式与例子](references/patterns.md)，无需默认加载整份参考。

- 每句话应增加事实、解释或判断；删掉重复前文的套话，不强制每段加意义、三点总结或下一步。
- 保留数字、日期、术语、来源和证据边界；不能把相关写成因果、计划写成结果、他人结论写成作者体验。
- 自然口吻不靠新增口头禅、情绪、采访或第一人称经历。缺材料时补原文或收窄论述，不编造细节。
- 按作者范例和文体选择语气，不把学术与技术说明改成销售文案。保留真实意见与有意义的不确定性。
- 正文先于标题；只委派标题时只改标题，不能借“去 AI 味”扩写正文。

修订后对照实际修改处，确认信息未丢失、事实未扩大；剩余具体问题局部处理。没有问题就结束，不为获得不同措辞继续重写。

task_read 有 notebook 时通过 notebook_patch 更新委派行，带最新 expectedRevision，保留 ID、顺序、来源、人工保护与非委派内容。只交付最终文字，不附带草稿、痕迹清单或自评；聊天只报完成情况与具体缺口。只读审核不直接改稿，保存和发布继续使用原有检查与授权。

模式参考源自 Wikipedia 的 Signs of AI writing，详细来源保留在参考文件中。模式用于编辑判断，不用于判定作者是否使用 AI。

新稿挂载本技能时，把表达要求融入一次写作，不据此追加全文修订或作者备注清洗。只有作者明确要求修改已有正文时才执行上述修订流程。
