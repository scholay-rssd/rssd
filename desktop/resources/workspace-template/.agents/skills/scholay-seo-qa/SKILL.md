# 只读质量检查

先明确本次是写作检查、发布准备还是工程验收，通过 article-index.json 定位稳定 ID 与 canonical 路径。只有云端指针时先说明需取回正文，不能用历史平台稿代替母稿。

## 一次检查，按需加载

- 阅读当前稿件和 [编辑清单](references/editorial-checklist.md)，按实际文体检查，不每次加载所有文体与平台规范。
- 核对事实或状态表述时读 [证据与状态](references/evidence-and-status.md)。关键数字、日期、实验对象、因果、现行步骤与许可必须有实际支持；不因普通常识没有逐句脚注阻断探索稿。
- 按 [范围与命令](references/repository-gates.md) 执行本篇或工程检查。同一版本已有可用结果时复用，发生变更只复核受影响项；未打包文章的包检查不适用。
- 只有文风判断需要时读 writing Skill 的 voice；涉及产品才读 product-capabilities 和 link-policy；特定文体或平台只读对应参考。用户要求完整参考文献、产品信息或公众号交付时执行 column-quality 的相关验收。

核对正文与来源、派生稿与母稿的实际差异：事实没有扩大，限定、引用和人工修改没有丢失，路径与真实图片有效。不要重复运行 copy-editing/humanizer，也不另起一轮全文改写。

## 边界与输出

本 Skill 只报告问题，不编辑、重命名、删文件、重生成图片、更新 SHA、preview、提交或同步。写作任务已明确授权修复时，由写作流程按问题局部修正后复查受影响项，不再为每个修辞问题单独审批；当前只读调用自身仍不改稿。

按严重程度给出有证据的问题及文件位置，简述通过项、未运行项与检查范围。没有可操作问题就明确结束，不要求为了“再审一遍”重复流程。事实缺口与证据边界只向作者报告并记入私有 verification，不冒称已核实，也不因备注中有待办而新增禁成稿门槛；发布准备的既有格式、版本和授权检查保持。

保存、防并发覆盖、发布授权、目标绑定、去重及公开回读仍由原流程执行。文件存在、preview 或提交意图都不等于公开发布，飞书状态单独报告。
