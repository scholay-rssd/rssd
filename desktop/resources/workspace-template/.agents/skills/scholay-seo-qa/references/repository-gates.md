# 按任务范围检查

独立桌面稿件工作区使用工作台现有检查与版本保存，不运行软件仓库的命令。以下 CLI 与工程检查只适用于打开统一 today 源码仓库的维护任务；缺少脚本时明确不适用，不安装发布引擎或创建另一份管线。所有检查只读，不更新正文、期望 SHA 或发布状态。

## 写作与改稿

对本篇进行一次事实与表达检查：数字、日期、对象、因果、出处、改写范围、隐私和关系披露；只对新增、变更、冲突或可能过期的事实补查原文。保留此前可用的核验记录，不能把来源可访问当作事实受支持。普通常识不逐句索要论文。

已登记的本机稿从统一根目录执行：

```bash
npm run editorial:check:article -- <article-id>
```

该命令校验本篇稳定 ID/路径、结构、引用的本地链接、真实配图及大小，并报告当前正文 SHA；不遍历其他正文，不加载发布包，不执行发布引擎测试。它不判断事实真伪、外链可访问性或隐私，也不代替人工编辑审阅。未完成的素材或图片如实保留为草稿，不冒充完整成稿。

Today 文章板使用现有格式、真实图片、当前 revision 和源稿 SHA 检查；同一正文版本已有对应检查结果时不再重复执行同一项。材料与正文变化后复核受影响的项。写作不运行工程全量检查。

## 本篇发布准备

只有当前任务涉及发布包时才执行：

```bash
npm run editorial:check:article -- <article-id> --package <package-slug>
```

此模式调用现有 loadPortableArticle，验证包确实绑定本篇、canonical/派生稿的严格字节 SHA、LF 及包内素材。失败交回写作或发布任务，不在 QA 中重算期望 SHA 来强行通过。云端稿先取回；归档指针不等于本机可发布正文。

按目标平台检查实际预览、引用、图片署名/许可、关系披露和样式；无需生成或检查未请求的平台变体。官网沿用其现有 prepare/版本/来源/图片检查，不要求建立第三方平台包。

外部提交仍必须绑定准确文章、平台和账号，取得当前授权，执行原有发布门禁与防重发。submit_intent 或结果不明时查原请求，不自动重试。公开回读、飞书同步分别报告；本地检查通过不能称为发布成功。

## 工程、Skill 与仓库改动

- 仅改 Skill/参考文档：运行对应 quick_validate.py 和本地链接检查；如果改变加载/路由逻辑，运行对应工作台测试。
- 改脚本、依赖、索引协议或发布引擎，或明确要求全仓验收：运行一次 doctor。它已经包含链接、JavaScript、可移植性/隐私、大小、文章索引及发布包检查，不再逐项重跑。
- 改发布引擎、发布配置、授权/回读协议或共享稿件保存逻辑：另运行一次发布引擎 self-test。该独立回归集不能用单篇检查替代；其中必要的包完整性回归保留。

```bash
npm run editorial:check
npm run editorial:test
```

按上述触发条件选择命令，不把两条都作为每篇写稿的必经步骤。记录运行范围、退出码及未覆盖项，不把单篇结果称为全仓通过。检查期间输入发生变化时，仅相关结果失效。

## 始终保留的边界

中文 canonical、平台/英文变体、运行状态各守原目录；令牌、Cookie、原始回执和截图留在忽略目录。检查当前修改与新增素材的隐私、可移植性和 Git 大小，不把凭证写进稿件。版本冲突保留人工修改，不靠更换 ID、清空保护或刷新哈希绕过。
