# 工具评测执行流程

本页只服务工具评测；科普和方法文不要套用这里的 4–7 工具要求。

## 1. 认领

从仓库 `_ops/inventory/topics.md` 的 R 组选一条工具评测题。指定平台，默认知乎。

## 2. Brief

先填写 [tool-review-brief.md](../assets/tool-review-brief.md)，再使用 [tool-review-article.md](../assets/tool-review-article.md)。必须填齐：

- `exam_task`（同一道题）
- `tool_ids`（4–7 个，含至少 2 个公认选手）
- `dimensions`
- `disclosure`
- `scholay_wins` / `scholay_loses`

过不去「删掉 Scholay，读者仍会选工具」这一关，就不要大纲。

## 3. Outline

顺序锁死：任务 → 披露 → 量尺 → 逐个工具 → 对照表 → 条件排序 → 收束。

## 4. Draft

每个工具同一结构。没跑过的格子写 `未测`。需要点名的论文必须真实，拿不准就用匿名课题描述。

## 5. QA

交给 `scholay-seo-qa`。只链 Scholay、或 Scholay 总第一，均为阻断项。

## 6. 发布与记账

平台公开回读后，由发布流程追加仓库 `_ops/inventory/published.md`。
