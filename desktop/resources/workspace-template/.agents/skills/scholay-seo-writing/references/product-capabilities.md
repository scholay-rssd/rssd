# 产品地图（写文章时用）

只写你验证过的能力。没走过的路径，不要写成教程。

官网：`https://www.scholay.com/`

## 读者真正在买的东西

不是「AI 学术平台」，而是：

- 把一个模糊问题收成可检索的需求
- 在大量文献里做多维筛选，而不是只扫摘要
- 让智能体的判断回到论文、PDF 和搜索结果
- 把一次检索变成组会、卡片、表格或写作骨架

## 可以写进文章的能力

来自现有功能地图和视频专项。写的时候用任务语言，不用菜单语言。

| 读者任务 | 可以露面的能力 | 不要写成 |
| --- | --- | --- |
| 找真正有用的论文 | 自然语言搜索、筛选、AI 解读 | 「强大的智能检索引擎」 |
| 看一篇是不是能用 | 详情面板、证据分层、相关文献 | 「一键读懂任何论文」 |
| 怕 AI 胡编 | 先给论文/PDF/搜索结果，再要求出处 | 「零幻觉大模型」 |
| 组会 / 选题 | 多维分析表、导出 md/表格 | 「智能选题系统自动发顶刊」 |
| 写作与审稿 | 骨架、挑刺、逐条回复 | 「AI 代写论文」 |

## 作者内部核验

逐项核对以下内容，结果与待办放入私有 verification；不要求每个能力后附一句边界声明：

- 它不能替你决定什么算贡献。
- 它不能把相关说成因果。
- 没有原文支撑的句子，只能标成未知。
- 额度、登录、导出格式如果会影响步骤，如实写。

## 禁止承诺

- 保证中稿、保证一区、保证替代导师
- 保证无幻觉
- 保证覆盖一切学科到同等深度

## 写进评测时的位置

对照本 Skill 的 `references/tool-review-rubric.md`。Scholay 默认拿来比的是：

- 证据约束、多维筛选、组会/清单产出
- 不是覆盖面、不是引用库、不是论文图谱

输的维度要写进同一张表，不要藏在脚注。

如果某篇需要链到尚未确认的功能深链，正文仍只写首页，并在 brief 里标 `LINK_TARGET_PENDING`。
