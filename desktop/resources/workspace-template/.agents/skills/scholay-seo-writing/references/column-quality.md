# 栏目成稿、参考文献与公众号验收

适用于六类工作台任务。用户要求产品化图文、参考文献或公众号交付时，执行以下成稿标准；普通素材收集仍可保留缺口。本页不改变选题、大纲确认和本地/公开交稿权限。

## 先确定读者拿走什么

每篇用具体读者、问题、结论和下一步组成 brief。标题要说清对象与变化，摘要交代事实和价值，正文不能只有资料摘抄。正文长度由证据与问题决定，不用重复套话凑字数。假想读者情境须写“设想/假设”，不能冒充采访或亲身经历；小标题用短句，具体数字与引文留在段落中。

| 栏目 | 必须讲清的内容 | 常见质量失败 | 公众号默认样式 |
| --- | --- | --- | --- |
| 学界犀闻 | 至少两件独立事件；统一主题下逐条讲事实与意义，末尾比较共同问题 | 把同一事件转载拆成多条，三段摘要拼接，没有编辑判断 | briefing 简报 |
| 学者观察 | 一件事的对象、方法、结果与意义；适用性与证据边界由作者内部核验 | 把相关写成因果，把机构宣传当独立验证 | academic 学术 |
| 学术开源 | 读者任务、输入输出、许可、依赖/成本、最小试用步骤、验收样本 | 只列功能；没有 LICENSE；把资料阅读说成安装实测 | technical 工具 |
| 学术情报 | 适用人群、活动/申请/通知日期性质、时区、行动入口、当前状态 | 把过去日期写成即将截止，擅自补时区或资格 | briefing 简报 |
| 昔日学术 | 完整发生日与日期依据、发生了什么、后来影响；解释边界由作者内部核验 | 把论文接收日写成发表日，现代工具画进历史场景 | academic 学术 |
| RSS 来源发现 | 原站、真实 feed、覆盖主题、格式、访问结果、最近条目时间与核验日分开 | HTML 页面当 feed；核验日当新闻日；候选自动订阅 | briefing 简报（验收报告） |

RSS 工作台仍只保存候选 board，不创建文章。用户另要公众号交付时，由验收/导出流程根据候选制作来源指南，存入 `_ops/`；不要让 RSS Agent 越过工具边界。

## 参考文献：可回查的顺序编码制

采用 GB/T 7714 风格顺序编码：正文事实附近放 `[1]`、`[2]`，文末列“参考文献”。每个编号恰好对应一个条目；同一来源重复使用同一编号。不用裸链接堆成来源清单，也不为凑文献数编造作者、卷期、页码、DOI 或日期。

- 论文：`[1] 作者. 原文题名[J]. 期刊, 年, 卷(期): 页码或文章号. DOI: [DOI](https://doi.org/实际DOI).` 作者多于三人可列前三位加 et al.；只写原文可核对的字段，在线优先发表且卷页未定则明确在线发表。
- 机构网页/通知/文档：`[2] 机构. 原文标题[EB/OL]. (实际发布日期或更新日)[引用日期]. [原文](https://真实地址).` 没有发布日期时省略该圆括号并说明“页面未标发布日期”；引用日期不可用来假冒发布日。
- 软件：`[3] 维护者. 项目名: 实际核验版本[CP/OL]. [引用日期]. [官方仓库](https://真实地址).` 未确定版本则省略版本；许可单列官方 LICENSE 引用，不能从仓库可见推断开源。
- RSS：官方入口文档与实际 feed 分开列 `[EB/OL]`；记录访问核验日，不给 feed 编造出版卷期。

每个数字、限制和可执行步骤都要对应真正支持它的来源，不能给一整段挂一个仅支持其中一句的编号。编号按正文首次出现顺序排列。

政策、申请、审稿与软件教程必须继续打开原页指向的实施细则、现行版本、更新/替代公告及下载入口。写“现在怎样做”前核对版本和生效日期；不能只读历史原始公告后靠“本文未读细则”免责声明验收通过。若关键细则无法读取，收缩为历史介绍，删除现行操作指令，并把测例记为待核验。

参考文献定稿前检查原页标题区、作者栏、页末版权与 Cite this post 区域，不能把正文提取器缺失的 author 字段解释成“原文未署名”。机构网页存在个人署名时按实际作者著录；只有确实无个人作者时才用机构责任者。

学术情报、昔日学术和学术开源仍保留各自固定的两个二级标题；参考文献和产品承接用第二个主章节中的三级标题，避免结构化字段转换丢失。新闻与观察稿可用二级标题。引文信息冲突或缺关键依据时记入私有 verification 待办；如实报告核验状态，不据此新增成稿门槛。

## 产品信息：读者下一步可以做什么

只有用户要求产品信息或选用产品模块时添加。使用一个与本篇任务直接相关的小段：读者输入什么、在 Scholay 哪一步继续、得到什么可核对结果，能力边界由作者内部核验，不紧接公开限定声明。用“本文由 Scholay 团队整理”披露关系，不虚构第一人称使用经历、实验或访谈。

当前可核对的公开入口是 https://www.scholay.com/ 。公开首页列有论文/期刊检索、个人文献管理、学术对话、LaTeX 写作、引用生成和稿件自查；这只证明产品公开说明，不证明作者逐一实测。可写“可从 Scholay 的论文检索入口继续查找原论文，再对照 DOI 和原文核对”，不可写“一键验证真伪”“保证零幻觉”。每篇最多一个可点击产品链接；价格、额度、导出细节没有实测就不写。

## 图文与验收

每篇规划至少两幅有不同信息用途的图，明确示意。手绘犀牛形象由 `scholay-rhino-illustration` 约束；文章 Agent 只安排 imageSlots，图库对话负责生图。图的日期、数字、许可或操作结论不能比正文更强。

公众号交付必须用桌面 `wechatHtml` 和栏目默认样式渲染实际正文，检查 390px 宽度的标题、表格、长链接、图注与参考文献，不只报告选中了样式。变体/HTML 放 `_ops/` 或忽略的本地预览目录，不覆盖 canonical。

验收分开记录：事实与引文逐项核对、产品段是否有承接价值、正文与结构化字段、图片实际可读和角色一致性、公众号渲染、Cursor 实际执行记录。任一项缺失就列明，不能用文件存在或脚本成功冒充质量通过。
