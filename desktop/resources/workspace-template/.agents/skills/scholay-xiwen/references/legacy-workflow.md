# 学界犀闻：选题、编排、图文交稿

先读 [中文写作规范](../../scholay-seo-writing/SKILL.md)、[步骤与板子约定](../references/structured-workflow.md) 和 [本地交稿约定](../references/local-draft-contract.md)。路径相对于当前稿件工作目录；桌面工作台通过 MCP 操作同一份索引和 Markdown。

## 工作台步骤模式

工作台统一使用 Cursor Auto。每次按钮只执行指定步骤：找材料、局部替换、编排、生成正文。读取 `task_read.workflow.sources`：`combined` 先本地 RSS 再联网补原文和缺口，`rss` 只读本地缓存，`web` 只联网。RSS 断开时 combined 可以继续联网，明确记录缺口；rss 模式保留已有材料并说明问题。

每条选题写 `acquiredVia: "rss" | "web"`；RSS 条目另存原始 `rssId`。来源机构和原文链接独立记录，检索渠道不等于新闻出处。已锁定项和同一事件去重规则保持不变。

任务授权由界面集中管理，常规工具无需逐次征求同意。不要修改权限配置、运行 shell 或改用其他工具绕过工作台；不要创建额外执行计划审批。文件已由界面附在提示中时不用再次读取。阶段结束通过 `task_update` 保存结果并停下，下一步由按钮触发。

继续正文生成时先读取已确认大纲、正文和已登记图片，保留人工修改及已有图片。不能因中途停止而新建文章。配图由用户在正文编辑后通过图库对话生成或导入；文章任务不调用生图或图片登记工具。云端交稿由界面完成，不自行提交。

## 1. 选题板

先调用 `task_read`，读取固定业务模式、主题、时间范围、revision、已有新闻和锁定项。默认近一周；每个模板可有自己的检索方向与范围，以当前任务板为准。优先用 Scholay RSS 的只读工具小批量检索，补充机构原文。不要为写稿批量刷新 RSS、改变未读状态或迁移数据库。

初始三个分栏，每栏一个槽位；用户可以编辑分栏名、增删分栏和槽位，最多五栏、每栏五条素材。只填已设置为智能采集的空槽，不自行补成三乘三。选题阶段不定文章标题；标题候选在编排阶段提供。每条记录实际来源机构、YYYY-MM-DD 发布日期、事实摘要、原文 URL。事件日期与报道日期分别说明。为同一事件的不同转载使用相同 `eventKey`；转载不能作为另一条新闻。原文没有日期或资料不够时说明缺口，由用户调整范围或数量，不猜日期、不编造补足。

使用 `task_update` 保存 `board`，带上 `task_read` 的 `expectedRevision`：

```json
{"titles":[],"sections":[{"id":"section-1","title":"分栏","items":[{"id":"news-1","eventKey":"event-1","title":"事实标题","summary":"支持的事实与边界","publisher":"来源机构","date":"2026-10-03","url":"https://example.org/primary-source","selected":false,"locked":false,"excluded":true}]}]}
```

严格按照当前板子的空智能槽位顺序执行：先 `task_read`，用 `task_topic_progress` 标记当前槽位 `searching`，核实一条后重新读取 revision 并保存完整 board，item.id 等于 slot.id。成功保存才开始下一槽；没有可靠材料则标记 `missing` 并写具体缺口。新卡片默认未选；用户勾选时 selected/locked 为 true、excluded 为 false。保留所有已有卡片、slots 和 slotCount，不重新添加 dismissed 记录的删除项。

上述示例只是字段格式。实际输出必须有真实来源。局部替换只更新指定新闻或分栏；保留其他项、锁定项及其 ID。不要解析聊天文字推测当前编排，更不要直接改 `.local/workbench/`。

**停在选题板，等用户第一次确认。** `topicConfirmed` 由桌面确认操作产生，AI 不能代填。

## 事实复核

- `date` 指所链接原文的实际发布日期，`dateBasis` 写明“论文在线发表／机构报道／近期报道回溯”；同一条另有研究日期时存 `publicationDate`。RSS 入库时间、转载时间、URL 路径日期不能直接当研究发表日。
- 回溯旧研究要显式说明旧日期，不为满足近期范围把旧结果写成新发现。每条至少核到机构原文、论文或官方项目，二手报道只作线索。
- 逐项核对数值与方向：“耗时增加 25%”不是“耗时为原来的 25%”；“未来开放”不是“已经开放”。期刊名称、实验对象、证据阶段必须与原文一致。
- 确认前检查三栏独立事件、来源日期、事实边界；含回溯材料的整稿标题和摘要也须说明。

## 2. 大纲

确认选题后，仅使用勾选材料，通过 `task_update` 写 `outline.titleCandidates`（三个标题候选）、`outline.selectedTitle`（从 0 开始）与 `outline.blocks`。类型包括 `title`、`summary`、`heading`、`paragraph`、`image`、`references`。块有稳定 `id`、可编辑 `text`、关联新闻 `sourceIds` 和 `locked`。至少安排两张有信息量的图片，图片块写具体视觉内容和需准确呈现的事实，不生成虚假实验照片或数字。

`product`、`signature`、`qrcode` 等尾部模块只在用户选用后添加。不要默认插广告、产品链接、二维码或署名。人工锁定块保留原文；素材变化后核对标记为 stale 的关联块，局部修订。

**停在大纲，等用户第二次确认。** `outlineConfirmed` 存在后才能创建初稿。

## 3. 正文编辑与配图占位

使用任务提供的固定 `articleId` 调用 `draft_create`，已有稿则 `draft_read` 后按当前 SHA 调用 `draft_save`。draft_create 只传 id、title 和 markdown；稿件的存放位置与栏目由工作台按任务类型决定，不要自行指定。标题变化不重建文章 ID。

结构遵循已确认大纲，事实旁保留来源和日期，综合解读与机构结论分开。篇幅随用户选定的分栏和材料展开，每条消息说明其事实、意义与边界。修改旧稿时只处理要求的段落，保留其他正文和手工修订。

正文生成时使用 `task_read.imageSlots` 中的相对路径，在对应位置插入 Markdown 配图占位。此阶段不调用生图工具，不用占位图声称配图完成。

正文编辑完成并保存后，用户在本地图库用对话生成图片，或在编辑器导入图片、从图库选择，替换占位。生图不属于内容工作台的任务模板。原图先登记到图库，由用户选用；生图提示不要预加水印，上传时沿用统一水印与 WebP 处理。文件缺失或生图失败时不显示成功，也不自动重复生成。占位未替换时不能交稿。

## 4. 交稿

本地 `draft_preview` 检查正文及图片；桌面“发布检查”核对来源、栏目、日期、图片与云端版本。默认留在本地。云端交稿即公开，只有用户明确要求发布时才 `cloud_prepare(intent=publish)`；`cloud_submit` 的桌面确认卡通过后执行。超时使用原请求的 `cloud_status`，不新建请求重发。

旧批量图文稿可参考其结构与来源记录，但不作为本次的新事实。其他业务不能复用此模式越过各自的字段校验。

原文核验使用[页面采集与预处理](../references/source-preprocessing.md)中的本地 RSS、桌面浏览器页面读取与公开网页提取；按实际来源类型与缺口记录证据。

## 产品化图文验收

用户要求参考文献、产品信息或公众号交付时，读取并执行[栏目成稿标准](../../scholay-seo-writing/references/column-quality.md)。逐篇核验事实与顺序编码参考文献，产品段承接本篇读者任务并披露关系；公众号使用本栏默认样式检查实际渲染。RSS 仅交候选与独立验收报告。此项优先于通用规范中“参考文献可选”的宽松建议。
