# 学者观察：讲清一件事

先读 [中文写作规范](../../scholay-seo-writing/SKILL.md)、[步骤与板子约定](../../scholay-xiwen/references/structured-workflow.md) 与 [本地交稿约定](../../scholay-xiwen/references/local-draft-contract.md)。路径均相对于 `editorial/`。工作台默认一栏一个核心事件；只处理人工已配置的智能槽位，勾选并确认后编排，确认大纲后生成正文。

## 获取材料

1. 检查已有文章标题、来源和稳定 ID，避免同一事件重复新建。已有稿的修订须获得当前任务授权。
2. 优先从桌面 MCP 的有限 RSS 候选中选取一个有明确读者问题的事件。查看实际工具参数后调用；不要为获取材料更改 RSS 阅读状态或执行全库刷新。
3. 阅读机构原文；必要时追到论文摘要、官方文档或发布记录。收集研究对象、方法、报告结果、发布日期与事件日期。网址日期不一定是页面发布日期。
4. RSS 只读查询出错时使用公开原文，记录替代方式；不在内容任务里修复数据库。
5. 选题应能回答“这次到底改变了哪一步”。仅有宣传口号或缺少可辨认事件的材料先淘汰，不拿常识扩写凑篇数。

原始发布日须从发布机构页面核对，不能沿用 RSS 的到达日期。政策上限要写清“超过后全部不资助”或“仅超额部分不资助”，不能只写模糊的“封顶”。日期与规则也需要逐张核对配图。

## 写作方法

- 从一个具体困惑开篇，接着说明团队做了什么，再解释它为何值得关注。
- 单篇以一个事件为核心。背景资料用于帮助理解，不把它写成另一篇聚合稿。
- 分开标明新闻事实、机制解释和编辑判断。尤其区分相关与因果、实验与量产、小鼠与人体、计划与已完成。
- 可使用“机制路径—观察意义—下一步”的结构，但不必每篇套同一种标题。通常 450–800 个汉字即可讲清一条消息，复杂题材可以更长。
- 不声称作者亲自做过实验或访谈；机构转述使用可回查链接。过早的推断用具体限制说明，不用一长段空泛免责声明代替内容。

## 配图与登记

- 每篇至少两图：一张清晰的机制/过程示意，一张结果适用范围、变量对照或时间线。不得用装饰图充当实验结果。
- 正文生成只安排占位图。编辑保存后，新图由本地图库对话生成并登记，用户从图库选用或导入有许可的照片，保留作者署名、示意说明与 alt 文本；文章任务不调用生图或图片登记工具。上传统一处理水印 WebP；历史 SVG 可保留，不能冒充本轮实际生图。
- 工作台任务中不指定 `column` 或 `archiveCategory`：稿件的存放位置与栏目由工作台按任务类型决定；保留本地未发布状态。
- 完成 brief、来源清单、图片预览和 [QA](../../scholay-seo-qa/SKILL.md)；检查旧文 SHA 未变。

## 交付信息

报告新增篇数、目录、核对到的来源日期范围和限制。工具输出失败不冒充采集成功，文件存在不冒充公开发布。需要多篇时先列出不同事件，再逐篇成稿。

原文核验使用[页面采集与预处理](../../scholay-xiwen/references/source-preprocessing.md)中的本地 RSS、桌面浏览器页面读取与公开网页提取；按实际来源类型与缺口记录证据。

## 产品化图文验收

用户要求参考文献、产品信息或公众号交付时，读取并执行[栏目成稿标准](../../scholay-seo-writing/references/column-quality.md)。逐篇核验事实与顺序编码参考文献，产品段承接本篇读者任务并披露关系；公众号使用本栏默认样式检查实际渲染。RSS 仅交候选与独立验收报告。此项优先于通用规范中“参考文献可选”的宽松建议。
