# SUCCES Content

Use SUCCES as a thinking scaffold, not a decorative label. Help the user turn an idea into content that is easy to understand, surprising enough to watch, concrete enough to believe, emotionally worth caring about, and carried by a story.

## Framework

- Simple: compress the argument into one clear sentence.
- Unexpected: create a hook that breaks the audience's default expectation.
- Concrete: use objects, scenes, numbers, examples, names, situations, and sensory details.
- Credible: separate fact, inference, and opinion; add sources, lived experience, or verifiable reasoning.
- Emotional: name the human stake, fear, desire, unfairness, dignity, or loss.
- Stories: arrange the argument as a change, conflict, dilemma, reveal, or personal scene.

## Workflow

1. Identify the audience, platform, objective, and desired audience reaction.
2. Write the one-sentence thesis first. If it cannot be stated plainly, ask one clarifying question or propose two possible theses.
3. Build a hook with a reversal, tension, or concrete incident. Prefer "X is not collapse; X is the destination" style reversals when supported.
4. Map the evidence:
   - Facts to verify.
   - Personal experience that can be used as credibility.
   - Inferences that must be framed as interpretation.
   - Lines that are too speculative or legally/socially risky.
5. Draft the structure as segments. For each segment, mark the strongest SUCCES elements in brackets, e.g. `[Simple, Unexpected, Emotional]`.
6. Add "gold lines" only where they sharpen the argument. Avoid slogans that replace proof.
7. End by restating the thesis with a larger value claim or audience question.

## Output Patterns

For a new script or outline, provide:

1. Title options.
2. One-sentence thesis.
3. Gold lines.
4. Segment-by-segment口播稿 with SUCCES tags.
5. Fact-check and risk-control notes.
6. Next edits that would improve the piece.

For revising existing copy, provide:

1. Diagnosis by SUCCES dimension.
2. Highest-leverage edits.
3. A rewritten version.
4. A compact table showing which segments now satisfy which elements.

For evaluating a concept, provide:

1. Whether the core idea is sticky enough.
2. The weakest SUCCES dimension.
3. One sharper thesis.
4. One stronger hook.
5. Specific missing examples or evidence.

## Style Rules

- Be willing to preserve the user's subjectivity, but help it become disciplined.
- Do not flatten complex issues into cheap binaries just to make a hook stronger.
- When using metaphors, make them serve the argument; do not let them become evidence.
- When a claim concerns current people, companies, institutions, legal/academic disputes, or public controversies, verify facts before treating them as factual.
- In Chinese口播, prefer short spoken sentences, strong verbs, and repeatable lines.
- Keep labels such as `[Simple]` useful and sparse; do not tag every sentence.


## Today 子弹笔记适配 · 2026-10-15 第一轮

在 Today 工作台内，本节决定交付方式。把面向读者的最终文字写入当前委派的内容行，保留 ID、来源和占位要求；聊天只报一句完成状态。草拟、SUCCES 标签、逐轮检查和润色过程留在思考中，不写进正文。不得调用 draft_create 或直接写成稿文件代替子弹笔记。

标题直接说明读者问题与收益。开篇给出具体信息，段落围绕事实、做法或可解释的判断展开。不强造反转、三点排比、金句或宏大结尾。删去“尚未校对”“仅供参考”“值得注意的是”等不提供信息的套话；必要边界应写成适用版本、地区、对象或前置条件。不能用含糊措辞掩盖缺失材料。缺少事实时补原文或改写为有材料支持的问题，不编造数据、采访、体验或实验。

这是写作规则，不是发布审核门槛。保存和推送只用确定性的格式检查。营销尾注仅使用作者已经勾选加入的节点。

## 真机写作修订 · 2026-10-16

先让读者看清对象、变化和实际用途。普通资讯可以直接开篇，不要求制造冲突、反转、金句或情绪。不在文章里展示 SUCCES 标签和检查过程；六个维度按材料需要选择，不必凑齐。

## 先正文，后标题 · 2026-10-16

在 Today 起草时，结构规划记录读者问题与证据，不预先交付正式子标题。先写具体正文，再从实际内容提炼标题；SUCCES 用来帮助表达已有材料，不要求每段都具备反转、故事和金句。若只委派正文，不越界改标题；若只委派标题，不反过来扩写正文。

## 首轮复盘 · 2026-10-16

选一个贯穿全文的具体问题或例子，后文继续使用同一对象。抽象概念只在读者用得上时引入，不为每节重造钩子和反转。研究文章的可记忆性来自问题、数值与推导的联系，不靠“改变一切”或泛化结尾。
