# 集中修订

先读需要修改的正文、相邻段落和用户要求。默认完成一次集中修订：先处理逻辑与重复，再处理句子表达；不要按检查维度反复通读和重写全文。

## 质量要求

- 每段推进具体事实、解释或操作；保留对结论有影响的条件和必要专业术语，删除重复引言、同义总结和无信息修饰。
- 保留数字、单位、日期、专名、引文、来源、因果强度和不确定性。补充或改变事实前核对支持它的原文；缺依据时说明具体缺口，不用更肯定的措辞遮盖。
- 尊重作者的语气、明确判断与个人表达。不能为了自然或说服力添加体验、情绪、收益、评价或采访。
- 先理顺正文，再检查标题是否准确覆盖内容；承诺过大的标题应收窄，不能扩写无依据内容来兑现。
- 修订后比较修改处与原文，确认没有事实漂移、引文丢失或误改范围。只有发现具体遗留问题才局部再改；不为了“再润色一遍”重写已合格段落。

## 按需专项

与 humanizer 或其他写作技能同用时，把它们作为本轮修订的检查维度，不各启动一轮全文重写。确有机械表达时参考 humanizer 的对应模式；没有问题就保留作者原文。

用户明确要求营销或转化文案时，才考虑产品背景、读者行动、收益证据与行动阻力；学术稿不默认强化情绪、销售承诺或“零风险”。收益和产品能力必须有材料支持，披露真实关系。

需要查漏时使用 [检查清单](references/checklist.md)，只看适用项，不再跑一轮完整修订。

## 工作台与交付

task_read 有 notebook 时，只通过 notebook_patch 修改本轮委派的节点，带最新 expectedRevision；保留 ID、顺序、来源、人工锁和非委派内容。不能借润色扩大权限，不调用 draft_create 或直接写成稿文件。

只交付最终文字，聊天简述完成情况或具体缺口，不附带多轮草稿、评分或自评。用户只要求只读审核时报告问题，不直接改稿。保存、SHA 防覆盖、发布授权、去重及公开回读沿用现有程序，不增加 AI 审稿门槛。

新稿挂载本技能时，把表达要求融入一次写作，不据此追加全文修订或作者备注清洗。只有作者明确要求修改已有正文时才执行上述修订流程。
