# 学术界的今天

先确认事件是否已在本地或云端作品库。相同事件补资料时沿用原 ID；不能把改写旧记录计为新文章。今天的纪念日、历史发生日、论文刊出日和后人的回忆日期分开记录。

## 材料与叙述

优先同期论文、档案、书信和机构原始记录。后来回忆可以使用，但在叙述中交代它是回忆，不假装看到了当日手稿。只有月份时不补成 1 日；发生、报告、出版是不同事件。来源链接必须仍能定位所引材料，跳转到首页不算定位成功。

用一个具体细节打开事件：当时要解决的困难是什么，做了什么尝试，什么关系或能力发生了改变。学术意义给出一个能解释的机制、算例或研究操作，避免只写“奠定基础、改变世界”。当代应用属于后续发展，不能塞回历史场景。无需每篇套人物生平、三点贡献和宏大总结。

先写正文，再概括必要的三级标题。保留读者理解这一天所需的时间线，删掉与事件无关的履历。图像若使用后绘作品或现代示意，应标明年代与性质；数学示意可用可复算图形，不把生成图当历史照片。

## Today 文章板

task_read 有 notebook 时，使用 notebook_patch 更新本次委派的 ID；新增结构用 task_update 并保留其他节点、来源、技能和人工锁。不要调用 draft_create 或直接写成稿文件。作者保存成稿后，从作品库预览发布。既有工作已授权，不增加逐步确认或“人工核验”门槛。

kind=history。固定二级标题为“事实摘要”“学术意义”；导语、图片、引用都置于对应章节内。摘要纯文本，进一步解释放学术意义，可用三级标题。字段 year 为整数，dateKey 为 MM-DD，domain、eventType、importance（S/A/B）、preciseToDay、sources 使用既有协议。普通重要事件可用 B，不靠最高等级吸引注意。完整年月日须能构成真实日期。

旧任务没有 notebook 时沿用其稳定 record ID 和既有 SHA 保存协议。已有云端内容先通过产品拉取最新版，保留原请求和版本；不直接改生产数据库。发布后回读历史日历、详情、日期与来源。保存与发布只做确定性格式检查，不用 AI 审核正文。
