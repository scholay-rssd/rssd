# 学术开源：围绕研究任务介绍工具

先读 [中文写作规范](../../scholay-seo-writing/SKILL.md)、[步骤与板子约定](../../scholay-xiwen/references/structured-workflow.md) 与 [本地交稿约定](../../scholay-xiwen/references/local-draft-contract.md)。路径均相对于 `editorial/`。工作台默认一个项目槽位；核对项目后停在素材板，用户确认后逐块编排，第二次确认后生成正文。

## 获取与筛选

1. 从本地 RSS 的工具线索、论文软件声明、维护者文档与官方仓库中发现候选。先查既有索引；不要重复写已有项目，除非版本变化或新的任务角度确有价值。
2. 优先覆盖不同科研环节：文献、文档解析、清洗、数据管理、分析、可视化、复现。不要以 star 排名代替任务适配性。
3. 读取官方 README、相关文档、仓库当前地址、归档状态、许可证。仓库迁移时使用实际新地址并保留旧来源记录。
4. API 返回 `NOASSERTION` 或未识别许可时读取 LICENSE/COPYING 正文。无法确认开源许可的项目不要当成已确认开源收录；公开源码与开源许可要分清。
5. 分别检查代码、模型权重、数据、插件的条款。记录核对日期，未来执行时重新检查；不要复用上一批过期的活跃状态或精确热度数字。
6. 事实核查由作者负责。资料阅读范围、未执行的安装或测试进入私有作者备注，公开正文按实际来源归属叙述，不写“本文未实测”来代替核查。旧任务没有 notebook 备注字段时使用既有私有归档，不向不支持的结构硬塞字段，也不把备注塞进正文或 status。有运行授权且确实安装测试时，才能报告本站环境、样本、操作和结果；不能把他人基准分数当本站实测。未解决的证据缺口保留在私有待办，由作者继续处理，不因此新增成稿门槛。

## 成稿

- 标题用“项目名 + 具体研究任务”，正文先说读者遇到的工作断点。
- 解释它处理哪一段流程，输入、输出及主要依赖是什么。列 3–5 步小规模使用顺序，避免给出未核对的安装命令。
- 说明适合的人群、不适用条件和实际维护成本。软件可用不等于资料、模型或分析结论可靠。
- 提供一个可执行的验收任务，例如抽查十份 PDF、重跑一份 notebook、核对一批图像坐标。此处写“建议怎样测试”，不能写成“我们已经测过”。
- 单项目介绍通常 450–800 个汉字。若做多个工具的比较测评，改走写作 Skill 的 tool-review 流程和同题量尺。
- 文末放官方仓库、必要文档、许可记录与核对日期。不要加入无关推广链接、隐蔽背书或精确但无法确认的用户数。

## 配图与交付

- 至少两张原创图：工作流程，以及输入/输出、能力边界或选用决策图。不要伪造软件截图。
- 正文生成只安排占位图。编辑完成后，新图通过本地图库对话生成并登记，再由用户选入文章；上传统一输出水印 WebP。文章任务不生图、不调用图片登记。历史 SVG 图源继续保留，外部截图/图片先核对允许使用的条件。
- 工作台任务中不指定 `column` 或 `archiveCategory`：稿件的存放位置与栏目由工作台按任务类型决定，`batchDate` 为 null。
- 登记稳定 ID、brief、项目来源和许可记录，运行 [QA](../../scholay-seo-qa/SKILL.md)。默认只保存本地，不安装软件、不上传或分发。

## 工作台结构化新稿

工作台 opensource 任务的固定 articleId 为 record-UUID 时，draft_create 需要 fields: {title,date,category,summary,value,url,relatedUrl,status}。date 为实际资料核验/收录日；category 从“文献与写作、科研 Agent、数据与评测、实验与仪器、生命与医学、基础设施”选择；url 为官方项目地址；status 是公开字段，只写已核实的资源状态，核验过程写入私有作者备注。Markdown 保留 `# 标题`、`## 项目简介`、`## 学术价值`，两张图片放在学术价值里，便于项目列表与详情共用同一个记录。已有普通文章 ID 继续沿用，不强制迁移。

图文正文使用 `task_read.imageSlots` 安排占位图片，用户编辑后通过图库对话生成或导入替换。不要虚构软件界面或跑分。默认本地交稿；云端交稿即公开，只有用户明确要求发布时才由界面用 intent=publish，并回读 kind、图片和实际公开版本；准备回执不等于公开成功。

结构化正文的一级标题之后直接进入上述二级标题。所有公开导语、引用和图片都放入对应章节，作者核验过程仍留在私有备注；不能在一级标题与首个二级标题之间另放文本，工作台会校验以防云端字段转换丢失段落。

原文核验使用[页面采集与预处理](../../scholay-xiwen/references/source-preprocessing.md)中的本地 RSS、桌面浏览器页面读取与公开网页提取；按实际来源类型与缺口记录证据。

## 产品化图文验收

用户要求参考文献、产品信息或公众号交付时，读取并执行[栏目成稿标准](../../scholay-seo-writing/references/column-quality.md)。逐篇核验事实与顺序编码参考文献，产品段承接本篇读者任务并披露关系；公众号使用本栏默认样式检查实际渲染。RSS 仅交候选与独立验收报告。此项优先于通用规范中“参考文献可选”的宽松建议。
