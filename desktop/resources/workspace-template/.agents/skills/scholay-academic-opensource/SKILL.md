# 学术开源：围绕研究任务介绍工具

从读者的研究任务出发，核对官方仓库、当前文档、版本、归档状态和 LICENSE/COPYING；项目迁移时保留实际地址和旧来源关系。不要根据 star 排名推断适用性。

- API 未识别许可证时读取许可正文，分别核对代码、模型权重、数据和插件条款。许可未确认不能称为已确认开源；记录实际核验日期。
- 解释输入、输出、依赖、成本、适用人群和限制。只提供已核对的安装或操作步骤；当前规则、版本和入口需要查当前原文，历史材料不能证明现在可用。
- 事实核查是作者的义务。必要事实、证据边界、资料阅读范围、是否实测及是否冒充实测只作作者内部核验，记录写入 verification；不要求正文声明，也不以“对读者判断必要”为例外补回。只有得到运行授权且实际执行后，内部记录才能记为本站测试；不能编造体验或实验。证据缺口与核查待办由作者处理，不交给读者，不新增成稿门槛。
- 可给出小规模试用建议；是否执行及核验情况写入作者备注，不伪造界面、性能、用户数或维护活跃度。
- kind=openSource 时保留固定二级标题“项目简介”“学术价值”，引用、图和三级标题放入对应章节，一级标题后不另放导语。fields 的 date 是实际资料核验/收录日，url 为官方地址，category 使用现有枚举；status 是公开字段，只写已核实的资源状态，不放“资料核验、未实测”等作者过程。普通文章保留原结构。

## 当前文章板

以 task_read 返回的 notebook 和本轮委派为准，使用 notebook_patch 更新指定节点并携带最新 expectedRevision。新增结构才使用 task_update；保留稳定 ID、非委派正文、来源、顺序和人工保护。已附的规则和材料无需重复读取，不增加选题、大纲或素材确认轮次。不调用 draft_create/draft_save 代替作者保存。

选题与取材明确后一次成文，在行文时将公开正文和对应行的内部说明分别写入 notebook JSON 的 blocks 与 blockNotes；不要写完后二次校对、全文润色或清洗来分流。正文单独满足篇幅目标，内部备注另留预算。事实核验贯穿取材与写作；缺口补来源或收窄论述，核验标准与记录不写成正文声明。

配图按信息用途和作者要求安排，不强制数量。真实图片保留许可、署名与来源，示意不能冒充照片或实验结果；已有图片占位须填实或由作者删除。只有当前委派允许时才处理图片。作者完成文章后由程序校验并保存；发布仍经独立预览、确认与公开回读，结果不明查询原请求。

## 按任务读取

- 只有 task_read **没有 notebook** 的历史任务才读取 [历史分阶段流程](references/legacy-workflow.md)，沿用其已有确认、ID 和 SHA 协议。
- 需要采集页面且当前材料不足时读取 [来源采集](../scholay-xiwen/references/source-preprocessing.md) 的对应渠道；文章板通过 sources 保存材料，不使用历史 board 槽位。
- 用户要求参考文献、产品信息或公众号交付时，按 [栏目成稿标准](../scholay-seo-writing/references/column-quality.md) 的对应部分检查；交付要求不增加日常写作审批。
- 用户要求独立审稿时使用 [只读 QA](../scholay-seo-qa/SKILL.md)；普通新写作把这些要求融入落笔，不默认追加审稿或全文润色。
